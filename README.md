# 系统触发面的按键白名单与确认票据治理

## 题面

排障手册要求值班同学按组合键落盘日志，结果一次误触把所有进程杀掉；另一次在掩码里关掉崩溃类能力以后，之前签发的确认票据还能用，机器直接被重启；触发口没有挂载时，工具直接空指针退出，现场连错误原因都拿不到；值班记录里连哪一次触发被拒绝、被谁触发都对不上，事后复盘只能翻终端历史。落点在 gsb/batch51-go-safety-c-18 的 sysrq_trigger_guard.go，类型 SysrqTriggerGuard 负责按键分级、掩码代际、确认票据与触发审计。

签名保持：NewSysrqTriggerGuard(cfg Config, port TriggerPort) *SysrqTriggerGuard、SetMask(mask string) error、Mask() string、MaskGeneration() uint32、Explain(keys string) ([]KeyVerdict, error)、IssueTicket(keys string, caller Caller) (Ticket, error)、Trigger(req Request) (Result, error)、SetLockLevel(level int) error、LockLevel() int、Faulted() bool、Audit() []AuditEntry、Snapshot() ([]byte, error)、Restore([]byte) error。

要修的行为：一、初始掩码全开、代际为 1；掩码按十进制位值解析，0 表示全部关闭，1 表示全部开启，其余按位组合；非法串报错且不改动现有掩码与代际，超出已定义位范围的掩码同样报错，解析失败时保持上一代掩码继续服务。二、掩码关闭某类能力后，该类按键一律拒绝且不写触发口。三、永久拒绝的按键即使掩码全开也拒绝。四、组合键按字符序列逐个求值，任一字符不通过整条拒绝，不能只看第一个字符就放行；Explain 对每个字符给出分档与是否启用，且不写触发口。五、未知按键报未知错误，不做任何写入，空请求按未知按键处理。六、调用者能力不足拒绝；锁定级别一档只放行低危键，二档全部拒绝，越界级别报错且不改变当前级别；能力与锁定级别判定先于票据校验。七、需要确认的按键没有票据时拒绝；票据与按键绑定、一次性、有有效期并带签发代际，低危键不给签票；票据过期后不得再兑换，也不能继续占着待签发票据的名额。八、掩码变更后已签发的确认票据立即失效，旧代票据不得再用。九、同一按键在去重窗口内重复触发只写一次并标记为去重，窗口过后重新写入。十、崩溃类按键成功触发后，后续任何触发一律失败，不能再碰触发口。十一、触发口不可写或未挂载时返回可诊断错误，不得崩溃。十二、审计按条数封顶保留最新，每条写明按键、调用者与结果，读取返回副本；快照恢复保住掩码代际、锁定级别、故障状态与审计。

硬约束：触发与掩码变更、票据签发互斥推进，任何时刻只能看到旧代或新代的完整白名单；同一按键的并发触发只能有一次真正写入；掩码代际在每次成功变更后递增，触发结果带上当时生效的代际；待签发票据数量封顶，超限拒绝。

验收：go test ./... 的 15 条必须全过，不改测试、不跳过、不按固定输入写死；并发触发与重启恢复自行验证；只做本地实现。
